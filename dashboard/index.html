    Reference · Same-Window Comparison secondary view — truncates slow timeframes to tiny samples

    Restricts every timeframe to the same trailing window. TradingView's bar limit means the longer histories simply do not exist at fast timeframes.

    Sweet Spot Finder

    Answers the two Portfolio Sim knobs that matter most — which timeframes to trade together and how many positions to run — by measuring every combination instead of guessing. This is the live version of PORTFOLIO_RECKONER.md; both run the same code (src/core/sweet_spot.js), so the tab and the doc cannot drift apart.

    Reads trade-log/*.csv only — no TradingView connection needed. Runs in its own process, so the rest of the dashboard stays responsive while a sweep is going.

    The Reckoner — shortlist scored out-of-sample, averaged

    Each config is scored in every out-of-sample window with the symbol universe re-picked inside that window's in-sample half, then averaged. This is the pass to act on — a single grid maximum is unstable, an average over a shortlist is not. Read the ordering, not the levels.

    Matched-Window Check — same calendar for every config

    Every pass above scores a config over its own span, so a fast 2-timeframe config and an 8-timeframe one were judged on different markets, not just different configs. This fixes the window to the stretch where all selected timeframes have data and re-ranks there, across rolling start dates. Ranked on total return over the window, not CAGR — the shared window is short, and annualizing it inflates by an exponent.

    Timeframe Contribution

    Average CAGR of every combination containing a timeframe against every combination without it, across all subsets. The largest and cleanest effect in the whole grid.

    Slot Count & Timeframe Count

    Max positions is also the position-size divisor (size = portfolio value / maxPositions), so falling slot counts raise CAGR and drawdown together. That is leverage, not edge — pick a risk point first, then optimize timeframes within it.

    Walk-Forward Honesty Check

    Rank every combination on the first part of the log, score it on the rest. Spearman rho is how much the in-sample ranking survived. Splits are on the trade-count quantile, never the calendar — the log spans 2016–2026 but almost all trades are recent, so a calendar midpoint lands in a near-empty region.

    In-Sample Grid — structure only, the maximum is not a result

    Every timeframe subset × slot count on all history. Shown because the aggregates above are built from it, but picking the best of these on the same data that produced the ranking is fitting, not measuring.

    Universe

    Ranked within the traded timeframes only, blended with each symbol's pooled all-timeframe percentile, with hysteresis so a held name is not dropped for slipping a place or two. Committing a re-pick appends an epoch — the replay then honours what was actually tradable at each point rather than applying today's list backwards.

    Sim Templates

    A Portfolio Sim configuration you decided to trade — its timeframes, slot count and universe — frozen together with the KPIs that justified it and tied to a brokerage account. The short code rides along on every webhook payload and manual-ledger position opened under it, so a fill can be attributed back to the configuration that called for it.

    KPIs are stored exactly as measured and are never recomputed. The trade log grows, so re-measuring would silently restate the numbers the decision was made on. Drift is reported below; to refresh a template, re-run the sim and save it again.

    Webhook Orders

    Every order this system sent to the trade executor, from status/webhook-sent-state.json. An entry stays "open" here until a matching close is sent — that is the same record the auto-close, the price-alert priority and the duplicate-send guard all key on, so this is the definitive list of what this system believes it has working. It is not a broker position report; for that see the Executor Portfolio card on the Signals tab.

    Open — sent, not yet closed

    Close sends a real closing order to the executor. Mark closed (no send) sends nothing — use it when you already closed the position directly at the broker, so the ledger stops asserting a position you no longer hold. Either way the row leaves this list and the auto-close stops watching it, so only mark closed what really is closed.
